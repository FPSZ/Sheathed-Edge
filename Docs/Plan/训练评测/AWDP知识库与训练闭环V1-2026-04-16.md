# AWDP 知识库与训练闭环 V1

## Summary

这份文档把 AWDP 方向的知识沉淀方式正式固定为：

- `agent / core / skills` 只保留路由、纪律、阶段和检查表
- 具体打法沉淀到 `Knowledge/awdp/playbooks`
- 已核对案例沉淀到 `Knowledge/awdp/cases`
- 机器可消费索引沉淀到 `Knowledge/awdp/indexes`

目标不是把更多字塞进 prompt，而是把：
- 红蓝常见打法
- 修补/回归/提交流程
- 做过的题与服务案例

变成可检索、可审查、可训练复用的知识层。

---

## 为什么要单独做 Knowledge/awdp

用户当前最在意两件事：
- 小模型不能因为 prompt 过长而跑偏
- 训练不能因为喂了很多题，就把答案特化成“只会这道题”

因此固定原则是：
- prompt 只讲路由与行为纪律
- playbook 讲可迁移的方法
- case 讲已验证过的具体实例
- index 讲让脚本、检索和 review 好用的结构化入口

## 为什么 playbook 和 case 要分开

### playbook
解决的是：
- “这类服务/漏洞/修补场景，一般怎么走”
- 要什么证据
- 哪些坑最常见
- 失败后退回哪里

### case
解决的是：
- “这次题/这台服务，具体发生了什么”
- 哪个证据最关键
- 哪个修补为什么 checker-safe
- 哪个 exploit 为什么可复用

分开以后，模型更容易学会：
- 先命中打法
- 再参考相近案例
- 最后落到当前服务自身证据

而不是把历史题当模板照抄。
