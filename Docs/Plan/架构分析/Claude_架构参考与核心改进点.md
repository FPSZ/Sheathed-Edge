# 藏锋 (Sheathed-Edge) 架构改进计划：基于 Claude Code 架构参考

通过借鉴业界最先进的 Agent 编排框架（Claude Code），我们提炼出以下三点高度契合藏锋项目核心目标（即 CTF / AWDP 等自动化渗透网关）的架构改进方向。这些方向将指导我们对 `gateway-go`（网关编排）和 `tool-router-rs`（工具执行与沙箱）进行深度重构。

---

## 1. 带隐式状态机的内层循环 (Orchestrator 会话自愈)

### 🔴 当前痛点
目前 Gateway 如果完全遵循 OpenAI 流式返回（`/v1/chat/completions`），一旦模型调用发生断点、出现工具格式错误、或者 Token 耗尽，就会将错误直接呈现给客户端（例如 Open WebUI），导致攻防断片和会话中止。

### 🟢 改进方案
在 `gateway-go` 的 `Orchestrator` (`RunNativeToolTurn`) 内部引入隐式的**多路状态机循环**。
- **拆分逻辑**：外层处理 HTTP 通信和计费记录，内层成为一个包含重试机制和恢复路径的循环引擎。
- **静默重试机制**：建立特定的错误拦截器。当发生内部可恢复错误（如 `prompt-too-long`，工具参数非预期，JSON 解析崩溃）时，**不抛出 500**，而是暂存于内存中进行内部 `yield`，使上下文回转到触发工具调用的上一时刻，利用报错信息让 LLM 再重试。
- **断路器 (Circuit Breaker)**：连续错误 3 次后强制截断，以保护 API 额度，只有这样才能被视为“真报错”并传递给 Web UI。

## 2. 极度悲观的工具安全模型 (Fail-Closed 安全与并发)

### 🔴 当前痛点
在渗透测试中，如果大语言模型在一个请求中生成了 5 个 Tool Calls。如果一味采用串行，效率低下；如果一味盲目并发，可能导致诸如“覆盖写入”或环境破坏之类的严重冲突（例如同时读写靶机里的漏洞利用脚本）。

### 🟢 改进方案
在 `tool-router-rs` (Rust端) 定义一套严苛且“假定不可信任”的工具元数据机制：
- **`isConcurrencySafe` 属性注入**：每个工具注册时必须明确声明。
  - 信息搜集类工具（`Cat`, `Nmap_Scan`, `Dir_Buster`）：设为 `true`。
  - 环境改变类工具（`Execute_Exploit`, `Write_File`, `Rm`）：设为 `false`。
- **流式并发切片调度 (Streaming Executor)**：在收到并行工具执行指令时，将所有连续处于 `isConcurrencySafe: true` 的工具自动丢入异步批处理池。一旦遇到 `false` 标识的服务，系统立即进入**独占锁屏模式**，切断与其他工具的交叉，等待其串行运行完毕再释放锁。
- **沙箱兜底**：不仅工具级做到资源锁管理，底层任何系统调用不匹配预期均直接熔断。

## 3. 上下文坍缩与分级压缩管线 (Context Engineering)

### 🔴 当前痛点
在真实的 CTF 或 AWDP 中，工具的返回日志是极度恐怖的（十几万字的漏扫结果、Nmap 冗余信息或者 Burp 返回包）。直接将这些结果丢入 `messages` 交由主模型处理，一通请求即可耗尽 128K/200K 上下文窗口限制并产生天价 Token 账单。

### 🟢 改进方案
在 `gateway-go` 进入下一次预测前，强制注入由多个轻重不同节点组成的**三级流水线处理管线**：
1. **轻度清洗节点（丢弃多余元数据）**：使用正则和 AST 将大量的 Base64 图形、无意义的重复 Hex Dump 块直接拦截剃除，保留结构化的 JSON。
2. **本地 Context Collapse（静态折叠）**：通过设定代码/日志阈值机制，比如超过 200 行的长日志默认折叠中间内容为 `[... Truncated 5000 lines ...]`，仅给 LLM 提供前后 100 行。
3. **AutoCompact（自动摘要降级）**：当即将触及整个工程上下文预算阈值警戒线（如可用 Token 不足 10000 时），系统自动向本地的 `llama-server` 等推断节点发出异步请求，让本地模型读取过去 15 轮长对话生成一份精炼摘要（总结），然后把过去的原始 Context 记录置换为大纲。这样可以在保证核心决策的前提下让长效对战环境得以维持。
