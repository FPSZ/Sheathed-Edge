# AWDP Core + Red/Blue Skills 分层实施说明

## 这次更新做了什么

这次把原来的：

- `agent router`
- `binary-core`
- `reverse skills`
- `pwn skills`
- `web skills`

升级成了：

- `agent router`
- `binary-core`
- `awdp-core`
- `reverse skills`
- `pwn skills`
- `web skills`
- `awdp-red skills`
- `awdp-blue skills`

目标不是把 AWDP 当成一个新题型，而是把它作为一层比赛模式和角色工作流接进现有 family 路由体系。

---

## 现在的分层关系

### 题型层
- `task_family = reverse | pwn | web | uncertain`
- `shared_domain = binary | web | unknown`

### 比赛模式层
- `competition_mode = ctf | awdp | unknown`
- `awdp_role = red | blue | mixed | unknown`

### 共享底座层
- `binary-core`
  - 只服务 `reverse / pwn`
- `awdp-core`
  - 只服务 `competition_mode=awdp`

### 家族 / 角色层
- `reverse skills`
- `pwn skills`
- `web skills`
- `awdp-red skills`
- `awdp-blue skills`

核心规则：
- `reverse` 和 `pwn` 继续是独立 family
- `awdp` 不是 family，而是 competition mode
- 红蓝不是题型，而是 `awdp_role`
- `binary-core` 与 `awdp-core` 都是内部共享层，不单独作为最终用户题型

## 这次新增了什么字段

会话层 / 训练层以后优先沿用这些稳定字段：

- `task_family`
- `shared_domain`
- `competition_mode`
- `awdp_role`
- `phase`
- `service_goal`
- `checker_safety_required`
- `primary_skill`
- `secondary_skills`
- `evidence_required`
- `fallback_if_fail`

其中：
- `competition_mode` 用来区分普通 CTF 和 AWDP
- `awdp_role` 用来区分红 / 蓝 / 混合
- `service_goal` 用来标当前是在 exploit、patch、regression、recovery，还是 submit

## 这次已经落地到控制面

Admin / Gateway 现在已经支持：
- `enable_agent_router`
- `enable_reverse_skills`
- `enable_pwn_skills`
- `enable_web_skills`
- `enable_awdp_red`
- `enable_awdp_blue`

并且是自动推导共享层：
- 开 `reverse` 或 `pwn` 时，自动挂 `binary-core`
- 开 `awdp-red` 或 `awdp-blue` 时，自动挂 `awdp-core`

也就是说：
- `binary-core` 不单独暴露成 UI 开关
- `awdp-core` 也不单独暴露成 UI 开关

## 一句话结论

现在系统已经不是“普通 CTF 路由 + 三个 family”了，而是：

- 题型仍按 `reverse / pwn / web`
- 比赛模式再按 `ctf / awdp`
- AWDP 再分 `red / blue`
- 共用底座由 `binary-core` 与 `awdp-core` 自动注入

后面如果要继续增强，优先往：
- `awdp knowledge / playbooks / cases`
- `checker-safe regression`
- `red reuse & submit workflow`

这三条线推进，不要再把所有经验堆回 `agent.md`。
