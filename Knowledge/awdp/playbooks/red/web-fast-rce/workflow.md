# Workflow

## Intake
- 先确认服务地址、端口、路由入口、认证状态
- 记录最短可访问路径和参数面
- 检查最近一次成功/失败请求，先用最小流量确认服务还活着

## Attack path selection
- 优先尝试最短链：未鉴权执行 > 上传到执行 > 模板注入 > 命令拼接 > 逻辑绕过到管理端
- 如果存在现成 exp，只先裁剪到本场可复用的最小版本
- payload 目标先固定为：`id` / `whoami` / 读取 flag 路径 / 回显一次标记串

## Verification
- 每次只改一个变量：路径、参数、编码、头部、文件名、内容体
- 一旦拿到命令执行或文件读取证据，立即转入 flag harvest
- 保留成功请求样本，作为 reuse 模板

## Escalation boundary
- 不在首轮浪费时间做高风险持久化
- 不把破坏性操作和批量利用混在同一轮验证里
