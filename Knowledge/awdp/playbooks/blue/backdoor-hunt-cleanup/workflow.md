# Workflow

## Hunt scope
- 优先看活跃路径：Web 根目录、上传目录、启动脚本、计划任务、systemd/service、登录脚本、常见临时目录
- 结合运行时证据：异常进程、可疑监听、近期修改时间、日志访问痕迹、未知账号
- 对二进制服务，额外看替换过的可执行文件、LD_PRELOAD、动态库投毒、wrapper 启动脚本

## Validate before cleanup
- 不因为文件名像 webshell 就直接删；先核对调用链、访问日志、内容结构、最近执行痕迹
- 对可疑账号、密钥、计划任务也要先确认是否被业务实际使用
- 能隔离就先隔离：改权限、重命名、下线入口、备份证据

## Cleanup
- 先备份原件和 hash
- 再删除/替换可疑文件、清理计划任务、移除恶意账号、恢复被改配置
- 清理后立即验证服务可用性和漏洞面变化

## Post-cleanup
- 记录 IOC、落点、时间线、恢复动作
- 把同类路径加入后续巡检清单
